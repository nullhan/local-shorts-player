# 本地音视频播放器（local-shorts-player）

一个抖音风格的**本地音视频**播放器：竖向全屏播放、上下滑动式切换、键盘 / 触摸手势控制、
支持音乐播放与移动端（锁屏控制、后台播放、防息屏）、<kbd>Delete</kbd> 快速删除当前媒体。

> 纯前端项目，媒体全部来自本机磁盘，不上传任何数据。

## 技术栈

沿用 `portal-web`（万象）的架构风格：

| 方案 | 组件 |
| --- | --- |
| 框架 | Vue 3（SFC + `<script setup lang="ts">`） |
| 路由 | vue-router（hash 模式） |
| 全局状态 | pinia |
| 构建工具 | vite |
| 样式 | Less（`style scoped lang="less"`） |
| 语言 | TypeScript |

### 自定义按键绑定

设置面板 → **快捷键** 分组，列出全部 15 个动作：

- 点某个动作右侧的按键按钮 → 按钮变成「按下按键…」→ 直接按下想绑定的键即可
- 支持组合键（<kbd>Ctrl</kbd>/<kbd>Alt</kbd>/<kbd>Shift</kbd>/<kbd>Meta</kbd> + 任意键），主键按物理键位识别（`KeyboardEvent.code`），不受输入法与键盘布局影响
- 按 <kbd>Esc</kbd> 取消录制；点按钮右侧的 ✕ 可解除该动作的绑定
- **冲突处理**：绑定到已被占用的组合键时，会自动解除原来那个动作的绑定并提示
- 底部提供「恢复默认按键」

实现要点：`utils/keymap.ts` 只做「组合键 ⇄ 动作」的映射与格式化，真正的分发在 `composables/useShortcuts.ts`。
全局快捷键不再硬编码具体按键，而是把事件压成组合键后查表。录制期间设置面板用**捕获阶段监听 + `stopPropagation`**
（外加 `store.capturingKey` 双保险），确保录制时不会误触发播放器动作。滚轮和鼠标点击不受绑定影响。

### 方向键步进可手动输入

`设置 → 操作 → 方向键步进`：既能选 3/5/10/15/30 秒预设，也能在「自定义」输入框里填 1–600 之间的任意秒数。
按住 <kbd>Shift</kbd> 仍是 3 倍步长（会实时提示当前值，如 `5s / 15s`）。

本项目使用 **pnpm** 管理依赖：

```bash
pnpm install
pnpm dev        # 开发服务器，默认 http://localhost:5188
```

构建与类型检查：

```bash
pnpm type-check   # vue-tsc --noEmit
pnpm build        # 类型检查 + 产物构建
pnpm preview      # 预览构建产物
```

> **关于包管理器**：仓库里还保留着一份早期的 `package-lock.json`（npm 的 lockfile）。
> pnpm 不会读取它，它也**没有和 `pnpm-lock.yaml` 保持同步**。请统一使用 pnpm 安装 ——
> 用 npm 会得到不同的依赖树，并给这个文件带来无意义的改动。

> **升级 pnpm 时注意**：`package.json` 里的 `packageManager` 字段会被 pnpm 12 记进 `pnpm-lock.yaml`
> （它会把包管理器自身也一起锁定）。改了它就必须重算 lockfile —— `pnpm install --lockfile-only` ——
> 否则 CI 会以 `ERR_PNPM_FROZEN_LOCKFILE_WITH_OUTDATED_LOCKFILE` 失败。

## 多文件夹（多来源）

可以**同时导入任意多个不同路径的文件夹**，每个文件夹是一个独立的「来源」。

在导入页可以反复点「继续添加文件夹」，已添加的文件夹会列出来，可逐个移除（只移除来源，
**不删磁盘文件**）。也可以一次拖入多个文件夹。

### 两个播放列表模式（设置 → 数据源 → 多文件夹播放方式）

| 模式 | 行为 | 适用场景 |
| --- | --- | --- |
| **合并为一个列表**（默认） | 所有文件夹的视频混在同一个列表，按排序规则上下切换 | 同一批内容分散在几处 |
| **每个文件夹独立** | 只播放当前选中的文件夹，在来源列表里点击切换 | 不同的片子各看各的 |

播放页底部会显示 `N 个文件夹 · 合并 / <文件夹名>`，点一下即可切换模式。
播放列表面板里每条视频都会标出它属于哪个文件夹。

### 删除与来源的对应关系

**删除永远在条目自己所属的文件夹里生效**，不会串到别的来源：

- 可读写来源（目录句柄模式）→ 真实移入该文件夹下的 `.shorts-trash/`，<kbd>Ctrl</kbd>+<kbd>Z</kbd> 还原回**原来那个文件夹**
- 只读来源（兼容模式）→ 只把条目移出列表，并给出明确提示

因此**允许混用**：一部分文件夹用目录句柄导入（可真实删除），另一部分用拖拽导入（只读），
两者可以同时存在，各自按自己的能力处理。

### 重复视频扫描跨来源

重复检测**始终覆盖全部来源**，不受当前播放列表模式影响 —— 这正是它最有价值的场景：
不同文件夹里的同一段视频也能被找出来。

结果里跨文件夹的重复组会打上「跨文件夹」标记，每个副本都标出所在文件夹，避免删错。
扫描结束后提示会说明跨文件夹的组数（如「发现 3 组重复视频，其中 1 组跨文件夹」）。

### 会话恢复

- 用目录句柄导入的文件夹会被记住（IndexedDB），下次打开可一键恢复**全部**文件夹
- 兼容模式（拖拽 / `webkitdirectory`）拿不到持久句柄，无法跨会话恢复
- 旧版本的单目录记忆会自动迁移成新格式，不会丢失

## 两种导入模式（重要）

浏览器出于安全限制，对本地文件的可操作能力分两档：

### 1. 目录句柄模式（推荐，Chrome / Edge）

点击「选择视频文件夹」→ 调用 File System Access API 的 `showDirectoryPicker({ mode: 'readwrite' })`：

- 自动递归扫描所有子目录，无需手动选多个文件夹
- 可反复添加多个文件夹；再次选同一个文件夹会**替换而不是重复添加**
- 记住目录句柄（IndexedDB 持久化），下次可一键「恢复上次」（支持多个文件夹）
- <kbd>Delete</kbd> 可**真实删除**磁盘文件：默认移动（复制）到目录下的 `.shorts-trash/` 回收站，可 <kbd>Ctrl</kbd>+<kbd>Z</kbd> 还原
- 可在设置中切换为「永久删除」，直接调用 `remove()` 抹除文件

### 2. 兼容模式（其它浏览器 / 拖拽 / 选文件夹）

- 拖拽文件夹到页面，或点击「选择文件夹（兼容模式）」
- 浏览器不会把绝对路径交付页面，因此**无法删除磁盘原文件**
- 此时 <kbd>Delete</kbd> 只在播放列表中移除该条目，界面会有明确提示

> 如果拖拽时浏览器提供了 `DataTransferItem.getAsFileSystemHandle()`，会自动升级为目录句柄模式。

## 切换动画（参考抖音）

上下切换视频时，**新旧画面同时全屏滑动**，旧画面向上（或向下）滑出屏幕的同时新画面从另一侧滑入：

- 纯 `transform: translateY(±100%)`，完全不使用 `opacity` 淡入淡出 —— 原实现用 `mode="out-in"` +
  透明度过渡，旧画面淡出后新画面才淡入，中间会露出黑底，就是那个"黑一下"
- 两个画面尺寸都等于视口且反向等速移动，任意时刻它们恰好拼满屏幕，**不会出现黑边或黑帧**
- 时长 300ms，缓动 `cubic-bezier(0.22, 0.61, 0.36, 1)`
- 旧实例在滑出期间继续播放，画面是"活动的"，不是静止帧

两个技术细节：

1. `.video-stage` 必须 `position: absolute; inset: 0`，否则两个实例会争抢文档流位置。
2. 切换瞬间会短暂存在两个 `VideoStage` 实例，而播放内核状态（`videoTime` / `videoPaused` / …）是模块级共享的。
   因此给每个实例分配一个 `stamp`，只有与 `useVideoControl.controllerStamp` 相符的实例才允许写状态，
   `unbindController` 也只卸载"自己"，避免旧实例的事件把进度条 / 播放状态写歪。

另外，深色渐变占位海报只在**首屏**显示：一旦成功渲染过一帧，后续切换不再显示海报，
否则滑入的那半屏会是一块暗色。

## 操作提示（OSD）

提示分**两级**，都从总开关出去：

```
设置 → 操作
├─ 显示提示        ← 总开关，关掉后一个浮层提示都不会出现（含删除、导入结果）
└─ 重要提示        ← 仅在总开关打开时可用；关掉后只保留音量 / 进度 / 倍速这类轻量反馈
```

| 级别 | 内容 | 位置 / 样式 |
| --- | --- | --- |
| 播放图标 | 播放 / 暂停 | 画面中央闪一个大图标（`PlayPulse.vue`），**无胶囊、无底色、无模糊层**，620ms 淡出 |
| 轻量反馈 | 音量、静音、进度快进/快退、倍速、画面适配、全屏 | 音量等用中央深色胶囊；进度用 ghost（无底色，只有一行带阴影的浅色文字，约 1.2s） |
| 重要提示 | 删除、撤销删除、导入结果、权限失败、恢复默认 | **底部居中条**（`toast`），不压画面主体，也不挡左侧操作轨道 |

> 重要提示原来放在屏幕正中心且不受开关控制 —— 这是设计失误。现在它既被总开关管住，也挪到了底部。

实现要点（`OsdToast.vue`）：

- 外层 `.osd-layer` 负责定位（`osd-pos-center` / `osd-pos-bottom`），内层 `.osd` 负责样式；
  过渡动画把**透明度放在外层、缩放放在内层**，这样不会去动定位用的 `transform`（写在同一个元素上必然互相覆盖）
- `store.showFeedback()` 只判 `osdEnabled`；`store.showOsd()` 判 `osdEnabled && osdImportant`，
  两者最终都走同一个 `pushOsd()`，逻辑集中在 `store/player.ts` 一处

## 控件不再乱弹

原来 `useIdle` 监听 `mousedown` / `keydown` / `wheel` 都会唤醒顶 / 底两条黑色渐变控制条，
于是"点击画面暂停"和"按 ←→ 调进度"都会闪出那两层黑条。现在**只有鼠标真的移动**才唤醒控件：

- 点击画面暂停、按方向键调进度、滚轮切视频 → 画面保持干净
- 需要控件时晃一下鼠标即可，2.6 秒无操作后再次隐藏

### 为什么控制条完全没有背景遮罩

这是一个踩过两次坑才想清楚的设计决定。

最初顶栏和底栏各自带一条渐变（`top-bar` 是 `0.66 → transparent`、`bottom-bar` 是 `0.78 → transparent`），
用户反馈出现「两层不同的遮罩 + 阶梯式的样式问题」。改成整个播放页只有一层 `.scrim`（全屏百分比渐变）之后，
问题**依然存在**——说明根因不是"两条渐变"，而是"全屏宽度的暗化"本身。

真正的根因：

> 竖屏视频在横屏窗口里走 `object-fit: contain`，左右会留出**纯黑边**。
> 而渐变是"把下面的内容压暗"，**把纯黑再压暗不会有任何变化**。
> 于是整屏宽的蒙版**只在视频那一列上可见** —— 它变成了一个比屏幕窄、
> 左右两条边是硬边的暗色矩形；再叠加"视频被压暗后与黑边的对比度下降"，
> 视频在顶部/底部看起来就像缩进去了一截，这就是那个"阶梯"。

**只要存在黑边，任何全屏宽的暗化都救不回来**（除非把黑边改成非纯黑，但那更难看）。

所以最终方案是彻底放弃整屏遮罩，改成「谁需要可读性，谁自带背景」：

| 元素 | 做法 |
| --- | --- |
| 顶栏 / 轨道的圆形按钮、播放键 | 自带 `rgba(18,18,26,.62)` 深色底 |
| 文件名 / 元信息、底部快捷键提示 | `text-shadow: 0 1px 4px rgba(0,0,0,.92)` |
| 进度条轨道、音量轨道 | `box-shadow: 0 1px 4px rgba(0,0,0,.55)`，从亮画面里分出来 |
| 分辨率角标、模式标签 | 本来就有自己的底色 |

> 顺带一提：`backdrop-filter` 也从这些控件上全部移除了。顶栏底栏会做 `opacity` / `transform` 动画，
> 而 `backdrop-filter` 放在带动画的祖先里会因为 backdrop root 变化产生矩形伪影 —— 这也是"只有顶部出问题"的嫌疑点之一。
> 面板（设置 / 列表 / 重复视频）同样是带 `opacity + transform` 的滑入动画，所以也不再使用模糊背景。

## 音乐播放与移动端

### 音频支持

导入时同时扫描视频与音频（mp3 / m4a / aac / flac / wav / opus / ogg / mka …）。

音频走**音乐界面**（生成封面 + 标题 + 专辑信息），视频仍走原来的全屏播放。

判定逻辑见 `utils/media.ts` 的 `mediaKindOf`：

- 只命中音频扩展名 → 音频
- 只命中视频扩展名 → 视频
- **两边都命中**（`.ogg` / `.webm` 这类容器既能装音频也能装视频）→ 先归为视频，
  由播放器按实际轨道处理

如果某个 `.webm` 其实是纯音频，按 <kbd>V</kbd> 或「设置 → 播放 → 界面呈现」手动指定
「始终音乐」即可。

> **实现要点**：音频用 `<audio>` 宿主而不是"零尺寸 `<video>`"。
> 属性与事件几乎完全一致（都继承 `HTMLMediaElement`），所以 `useVideoControl`
> 那套播放内核一行都不用改；但移动端系统会按**音频会话**处理，
> 锁屏与媒体通知的行为更正确。

### 移动端适配

### 锁屏控制（Media Session）与防息屏（Wake Lock）

设置 → **移动端**：

- **锁屏 / 通知栏控制**：把当前曲目交给系统，Android / iOS 的锁屏、
  通知栏、耳机线控、车载蓝牙都能控制播放与上下曲，**不需要装 App**。
  含 `seekto`，所以车机拖动进度条也生效。
- **播放时阻止息屏**：仅音乐模式生效 —— 听歌时屏幕自己灭掉会打断操作；
  视频场景不启用，因为用户本来就在看。

两者都做了能力探测，不支持的浏览器上开关会置灰并说明原因；
非安全上下文（非 https / localhost）会额外提示。

### 后台播放稳定性（Service Worker）

`public/media-sw.js` 接管媒体请求：

- 带 `Range` 的请求**直接放行**（缓存 206 分片会让后续播放读到残缺数据）
- 完整 200 响应写入 Cache，网络中断时用缓存兜底
- 覆盖式更新（`skipWaiting` + `clients.claim`），不做全量预缓存以免浪费流量
- 注册失败静默忽略，`file://` 下不注册（非安全上下文）

> 手机上装到桌面（添加到主屏幕）后以 PWA 方式运行，后台播放最稳。

## 重复视频检测与清理

设置 → **重复视频** → 「扫描并清理重复视频」，会打开一个**整屏对话框**（左预览 + 右列表）。

面板里能做什么：

- 点「开始扫描」，实时显示进度（已读取字节数 / 需校验文件数），随时可取消
- **点列表里任意一行 → 立刻在左侧预览**，确认过再决定保留哪一个；<kbd>Esc</kbd> 先关预览、再关面板
- 预览区下方有「在播放器中打开」（必要时自动切到该文件所属的文件夹）与「标记为删除 / 保留」
- 结果按「内容相同」分组，每组显示体积和可释放空间；默认**每组保留第一个**，其余自动勾选
- 全选/取消任意文件后点「删除选中」，会先弹出确认条（永久删除模式会额外标红警告）
- 删除沿用设置里的「Delete 键行为」：移入回收站（可 Ctrl+Z 逐个还原）或永久删除；
  兼容模式（拖拽导入）下无法删磁盘文件，只会把多余的条目移出列表

### 预览与主播放器的声音

预览用的是同一个文件的 `blob:` 地址（`item.url`），所以**兼容模式也能预览**。两个细节：

- **预览开始时会把主播放器暂停**，否则两路音频会同时响；关闭面板时**只恢复"被预览抢停的那一次"**，
  不会把用户自己暂停的视频擅自放起来。
- 面板是模态的，打开期间**全局快捷键整体让位**（`useShortcuts` 里直接 return）。
  这点必须做：否则 <kbd>Delete</kbd> 删的是"背后正在播放的那个视频"而不是勾选的副本，
  <kbd>Space</kbd>/<kbd>↑↓</kbd> 也会去操作背后的播放器。

### ⚠️ 预览视频必须绝对定位（和 `.video-el` 是同一个坑）

```less
.preview-stage { position: relative; flex: 1 1 auto; min-height: 0; overflow: hidden }
.preview-video { position: absolute; inset: 0; width: 100%; height: 100%; object-fit: contain }
```

一开始写的是 `display: grid; place-items: center` + 视频 `max-width/max-height: 100%`（看起来最自然），
结果**窗口一大、视频一竖屏就爆**：可替换元素带固有宽高比时，grid item 的 `min-height: auto` 会解析成
**固有高度**（竖屏视频上千像素），而百分比 `max-height` 在"高度不确定"的容器里会解析成 `none`，挡不住它。
于是 `min-content` 被撑到上千像素，一路顶开 grid 行 → 左栏整体变高 → 预览区下方的按钮被挤出卡片、
右侧分界线跟着错位。

配套还要三处归零：`.preview-pane { min-height: 0 }`（grid item）、
`.result-body { grid-template-rows: minmax(0, 1fr) }`（显式给行一个可收缩上限）、
`.preview-pane { overflow: hidden }`（兜底，绝不让内容溢出去压别人的区域）。

**通用规则：任何 `<video>` / `<img>` 放进 flex 或 grid 容器时，要么绝对定位铺满 + `object-fit`，
要么显式写 `min-width: 0; min-height: 0` 并在容器上 `overflow: hidden`。** 本项目已经栽过两次。

### 怎么判断"内容一模一样"

新增 `src/utils/hash.ts`，分两层：

1. **按体积分桶**（关键优化）：体积不同的文件不可能内容相同，直接排除，不需要读盘。
   一个几百个视频的目录里，通常只有极少数文件体积重复，这一步能省掉 95% 以上的读取。
2. **对同体积文件算内容指纹**：`crypto.subtle.digest('SHA-256')` 分块计算，每块 8MB，
   最后把「文件长度 + 各块摘要」再摘要一次。因为 `crypto.subtle.digest` 只接受完整 Buffer，
   几 GB 的文件一次性读进内存会把页面撑爆；分块后内存占用恒定。

几个值得注意的点：

- **不是 MD5**：浏览器没有内置 MD5，纯 JS 实现只有几十 MB/s；SHA-256 由浏览器原生实现，快得多也更强。
- **不是标准摘要**：分块方案使得指纹依赖分块大小，所以**不能拿去和 `md5sum` / `sha256sum` 对照**。
  对本功能无影响 —— 比较的双方体积必定相同（体积不同先被排除），同体积就必然分块一致，
  因此该摘要等价于"整份内容的指纹"。
- **需要安全上下文**：`crypto.subtle` 只在 https / localhost 可用。不满足时面板会直接提示，不会静默失败。
- **体积相同但内容不同不会误判**：指纹会区分开（例如同一段素材的两种剪裁恰好体积一致）。
- 文件名完全不同、散在不同子目录里的同一份视频，同样能被识别出来 —— 这正是看内容而不是看文件名的意义。

## 打开所在文件夹

按 <kbd>O</kbd>，**在系统资源管理器中打开并选中当前视频**。目标是谁取决于你在哪儿按：

- 播放页：当前正在播放的那个视频
- 重复视频面板打开时：你选中的那一项（优先正在预览的，其次第一个被勾选的）。
  这也是为什么该面板拦截全局快捷键时**唯独放行这一个动作** —— 它是只读的，且天然需要跨面板工作。

### 它为什么需要一个本机小程序

浏览器**故意**不提供两样东西，这不是配置问题：

1. **没有打开资源管理器的接口**。没有任何 API 能"在资源管理器中显示"某个文件。
2. **拿不到绝对路径**。`FileSystemHandle` 只暴露 `name`（文件夹名），整体路径在设计上就不给页面 ——
   这是防止网站探测你磁盘结构的措施。

> 曾经试过 `showDirectoryPicker({ startIn: 目录句柄 })`：`startIn` 确实接受 `FileSystemHandle`，
> 对话框也能开在正确目录，但它本质是**权限授予对话框**（"选择允许此网站查看的文件夹"），
> 而且目录选择器**只列子文件夹、不列文件** —— 文件夹里只有视频时它就是空的。
> 结论：它做不到"打开资源管理器"，所以换成了小助手方案。

所以最后一步交给 `tools/reveal-helper.mjs` —— 一个**零依赖**的 Node 小程序：

```bash
node tools/reveal-helper.mjs                 # 默认监听 127.0.0.1:17897
node tools/reveal-helper.mjs --dry-run       # 只打印将要执行的命令，不打开窗口（建议先这样试）
node tools/reveal-helper.mjs --port 18000
node tools/reveal-helper.mjs --allow-origin https://your-site.example
```

页面按 <kbd>O</kbd> → 请求 `http://127.0.0.1:17897/reveal` → 小助手执行
`explorer /select,"<完整路径>"`。**参数引用做对了**（路径带空格也没问题），并且文件已不在时会退一步打开它所在的文件夹。

### 配置一次

浏览器不给绝对路径，所以每个来源的根目录要**手填一次**：

播放页 → **设置 → 文件夹 → 配置本地小助手** → 填入根目录完整路径（可在资源管理器地址栏直接复制，如 `D:\videos`）→
点「校验并保存」。校验会拿该来源的第一个视频去问小助手"拼出来的路径存在吗"，通过才保存；
失败时会把尝试过的路径都列出来，方便你看出少填/多填了哪一层目录。

**小助手没在运行时怎么办**：同一个 <kbd>O</kbd> 会**退化成应用内筛选** ——
把播放列表收窄成"只看这个文件夹"（等效于下面那节说的跳转），保证按键永远有反馈，不会出现"按了没反应"。

### 两种导入模式都能用

小助手只需要"登记的根目录 + 相对路径"，不需要目录句柄，所以**拖拽 / `input` 导入的兼容模式也能用**
（旧方案只有句柄模式可用）。两种模式下相对路径的含义不同（兼容模式的 `webkitRelativePath` 会带上根目录名），
小助手按几种组合依次尝试、**以磁盘上是否真实存在为准**，所以登记"被拖入的那个文件夹"或"它的父目录"都能对上。

### 安全边界

- 只监听 **127.0.0.1**，不对外网开放。
- 只响应**白名单来源**：默认 `https://nullhan.github.io`，加任意 `http://localhost:*` / `http://127.0.0.1:*`；
  其它来源返回 403（否则任何网站都能指挥你本机弹窗口）。要放行别的域名用 `--allow-origin`。
- 拒绝带 `..` 的路径段，防止路径穿越。
- 唯一的动作是 `explorer /select,` —— 不改动、不删除任何文件。

### 一个已知的部署陷阱

页面部署在 **https** 上时，访问本机服务要过浏览器的 Private Network Access 预检（小助手会应答
`Access-Control-Allow-Private-Network: true`）。万一还是被拦（个别版本策略不同），
改用本地地址打开页面即可绕开：`npm run dev` / `npm run preview`（本机页面访问本机服务不受这条限制）。
配置面板里也写了这条提示。

## 只看某个文件夹（应用内跳转）

同一个 <kbd>O</kbd> 在不满足"打开资源管理器"条件时（小助手没运行、或该来源还没登记根目录）
会退化成**应用内跳转**：把播放列表收窄成同一个文件夹里的视频。

- 取当前视频的「来源 + 相对父目录」做筛选，**画面不中断** —— 当前视频本来就在那个文件夹里，
  过滤后它仍在列表中，所以只是列表变短，不会跳走或重播
- 播放列表面板顶部出现筛选条：`只看 [某系列A] 3 / 128` + 「显示全部」；播放页底部也有一个可点的状态标签
- **再按一次 <kbd>O</kbd>** 或点这两处任一即可退出（<kbd>Esc</kbd> 不管这个，它管全屏和面板）
- 生效范围：<kbd>↑↓</kbd>、滚轮切换、播放列表、删除后补位都只在这个子集里；
  **重复视频扫描仍是全量**，设置项照旧；排序依然生效，只是在子集内排
- 多文件夹合并模式下按「来源 + 文件夹」双重匹配，不会把两个文件夹里的同名目录混在一起
- 该文件夹里的条目被删光时自动解除筛选，不会卡在空列表上

用不上资源管理器、又不想跑本机程序时，这就是零安装的那个替代方案。也可以只当"就地比对同一文件夹的多个视频"来用。

## 画面适配

默认 **完整显示（contain）**：保留原始长宽比、不裁切，画面完整可见，多余空间补黑边。
可在「设置 → 画面 → 画面适配」或按 <kbd>A</kbd> 循环切换：

| 模式 | `object-fit` | 效果 |
| --- | --- | --- |
| 完整显示（默认） | `contain` | 保留比例，完整显示，两侧或上下补黑边 |
| 填满裁切 | `cover` | 保留比例，填满容器，超出部分裁掉 |
| 拉伸铺满 | `fill` | 填满容器，但画面比例会被拉伸变形 |

左下角会显示当前视频的原始分辨率与比例（如 `480×854 · 9:16`），便于判断画面是否被裁切。

> **实现注意**：`.video-el` 必须绝对定位铺满容器，不能用 `display:grid; place-items:center` + `width/height:100%`。
> 后者下视频的**固有宽高比会给出一个更大的自动最小尺寸**，把网格行撑得比容器更高 —— 竖屏视频能高出容器数百像素，超出部分被 `overflow:hidden` 裁掉，表现为"被放大且居中、看不到全貌"。

## 画面转向（逐视频）

有些视频是斜着拍、甚至整个倒过来的，需要在播放器里单独纠正。

设置 → **画面**：显示当前视频的转向状态，并提供「顺时针 90°」「水平镜像」「复位」三个按钮。
左侧操作轨道上也有一个转向按钮（有转向时高亮），快捷键 <kbd>R</kbd> 旋转、<kbd>Shift</kbd>+<kbd>R</kbd> 镜像。

**转向按视频逐个记录**，靠 `VideoItem.id`（相对路径 + 体积 + 修改时间 的 hash）关联：

- 切换上下视频不会互相影响 —— 修好倒着的那一个，其它正常的视频保持原样
- 记录写在独立的 `localStorage` key `local-shorts-player:transforms` 里，
  重新打开同一个文件夹时 id 不变，所以纠正结果依然有效
- 回到「原始方向」的视频会自动从记录里删除，不会无限膨胀；设置里也提供「清除全部转向记录」

### 90° 旋转为什么要用容器查询单位

旋转 90° 时，元素盒子的长和宽必须**互换**，旋转后的视觉边界才正好等于容器；
否则一个 1600×900 的容器里，旋转后的画面会有一部分跑到屏幕外被裁掉。

```less
.video-stage { container-type: size; }          /* 提供 cqw / cqh 基准 */

.video-el {
  position: absolute;
  top: 50%; left: 50%;
  width: 100cqw;                                /* 默认：容器宽 */
  height: 100cqh;                               /* 默认：容器高 */
  transform: translate(-50%, -50%) scaleX(var(--flip, 1)) rotate(var(--rot, 0deg));
}

.rot-90, .rot-270 { width: 100cqh; height: 100cqw; }   /* 互换 */
.rot-90 { --rot: 90deg }  .rot-180 { --rot: 180deg }  .rot-270 { --rot: 270deg }
.flipped { --flip: -1 }
```

几个关键点：

- 用 `--rot` / `--flip` 自定义属性组合出 `transform`，而不是让 `.rot-90` 和 `.flipped` 各自声明 `transform`
  —— 两个类都写 `transform` 时只有后声明的那个生效，没法叠加
- 居中改成 `top/left:50% + translate(-50%,-50%)`，因为旋转后盒子尺寸与容器不同，需要一个稳定的中心点
- `scaleX` 写在 `rotate` **左边**：CSS transform 是从右往左作用到点上，所以先旋转再按屏幕水平轴翻转，
  这样即使画面已转 90°，「水平镜像」依然是屏幕上的左右翻转
- 老浏览器不支持 `cqw/cqh` 时，`width: 100cqw` 会被整条丢弃导致宽度变 `auto`（画面尺寸失控），
  所以额外用 `@supports not (width: 100cqw)` 显式兜底成 `100%`

## 偏好持久化

以下设置会自动保存到 `localStorage`（key: `local-shorts-player:prefs`），下次打开自动恢复：

音量、静音状态、倍速、方向键步进、播放模式、切换后自动播放、删除方式、画面适配、
操作提示开关（总开关 + 重要提示）、播放列表排序字段与方向、全部按键绑定。

设计要点：

- **首屏同步读取**：在 store 初始化时同步 `loadPrefs()`，避免"先渲染默认值再跳变"的闪烁
- **写入防抖 300ms**：拖动音量滑块会高频触发，实测 25 次连续改动只产生 **1 次**写盘
- **隐藏前强制落盘**：监听 `pagehide` / `visibilitychange`，防止在防抖窗口内关闭页面丢数据
- **脏数据兜底**：`loadPrefs()` 逐字段校验类型与取值范围，遇到旧版本 / 被手改 / 损坏的 JSON 一律回落到默认值，不会把状态带崩
- **存储不可用静默降级**：隐私模式或禁用存储时读写都静默忽略，不影响播放
- **不持久化的内容**：播放列表、目录记忆（走 IndexedDB）、播放进度 —— 这些属于隐私或易失效信息

设置面板底部提供「恢复默认设置」一键还原。

> 存储分工：普通偏好（可 JSON 序列化、需要同步读）用 `localStorage`；
> 逐视频的画面转向另起一个 key（`local-shorts-player:transforms`），避免把"配置"和"逐文件数据"混在一起；
> 目录句柄（`FileSystemDirectoryHandle` 无法 JSON 序列化）用 `IndexedDB`。

## 实现要点

- **滚轮切换做节流**：累积 `deltaY` 超过阈值才切一次，切完加 260ms 锁，避免触控板一次滑动连切多条。
- **按键不硬编码**：`useShortcuts` 只把事件压成组合键再查 `keymap`，加动作只需在 `utils/keymap.ts` 补一条定义 + 默认绑定。
- **切换动画用 stamp 隔离**：同时活着的新旧两个 `VideoStage` 实例共享一份播放内核状态，靠 `controllerStamp` 保证只有活跃实例能写。
- **两级标识区分"列表内唯一"和"跨会话稳定"**：
  `VideoItem.id` = `来源id:contentKey`，带来源前缀，用于 Vue key / `currentId` / 删除记录；
  `contentKey` = 相对路径 + 体积 + 修改时间，不含来源，用于画面转向记录。
  两个文件夹里同名同体积的文件必须靠 `id` 区分，而转向记录又必须在重新导入后仍然有效 —— 单一字段无法同时满足。
- **播放列表是派生的，不是可变状态**：`allItems` 是唯一数据源，`playlist` 由它按
  「合并/分开 + 排序规则」`computed` 得出。删除 / 还原只改 `allItems`，
  靠一个 `sortVersion` 计数器触发重算。这样两种模式和排序永远一致，不会出现两处状态不同步。
- **画面转向逐视频存**：`utils/transforms.ts` 用 `contentKey` 做 key；不要把这类纠正做成全局开关，否则修好一个就会弄坏其它正常视频。
- **删除按来源解析句柄**：`removeCurrent` / `removeMany` 都先查条目自己的 `sourceId` 再取该来源的目录句柄，
  所以混合了只读来源时也能各自走对的路径（真实删除 vs 仅移出列表）。
- **偏好逐字段校验**：`loadPrefs()` 会校验每个字段的类型与取值；新增偏好时必须同步补进 `DEFAULT_PREFS` 和 `sanitize()`，
  否则旧数据里缺这个字段会让它变成 `undefined`。
- **播放内核状态集中**：`useVideoControl` 持有 `currentTime / duration / paused`，由 `VideoStage` 单向写入，进度条等只读，避免组件间互相找 DOM。
- **删除后自动续播**：从列表移除后索引自动落到下一个，列表清空时展示空状态并提供撤销入口。
- **大目录性能**：扫描时增量回报进度（已发现 N 个视频 / M 个目录）；列表项使用 `content-visibility: auto` 降低渲染开销。
- **格式兜底**：常见 mp4/webm/mkv/mov 等 20 余种扩展名；浏览器无法解码的编码（如 HEVC）会显示错误遮罩并提示转码。
- **重复检测先按体积分桶**：体积不同的文件不可能相同，因此绝大多数文件不需要读盘；
  只有同体积文件才计算内容指纹（`utils/hash.ts`），这是整条链路的性能关键。
- **控制条不做整屏遮罩**：竖屏视频 + `contain` 的黑边会让任何全屏暗化变成带硬边的暗色矩形（详见上文）。
  改为控件自带底色 + 文字阴影，`backdrop-filter` 也一并移除（它放在带动画的祖先里会产生矩形伪影）。

## 已知限制

- 目录句柄模式下删除采用「流复制到 `.shorts-trash` 再删除原文件」的方式（Web 端没有 `rename` 接口），超大文件会有一秒左右的复制耗时。
- 兼容模式无法真正删除磁盘文件，这是浏览器安全模型决定的。
- 首次播放需要一次用户手势（点击）才允许出声，已在进入播放页时自动尝试一次并在失败时静默降级。
- 重复视频扫描需要把候选文件完整读一遍。只有同体积文件会被读取，但如果目录里恰好有多个几 GB 的同体积文件，
  扫描仍需要相应时间（面板里有进度和取消）。
- 内容指纹是**分块 SHA-256**，只能在本应用内部比较，不能与 `md5sum` / `sha256sum` 的输出对照 —— 后者需要标准摘要。
- 没有整屏控制条遮罩，所以画面极亮时顶部的文件名/提示文字可读性依赖文字阴影，极端情况下仍可能偏浅。
- 「打开所在文件夹」要真正打开资源管理器，必须借助 `tools/reveal-helper.mjs` 这个本机小程序 ——
  浏览器没有相应接口，也不给页面绝对路径（这是刻意的隐私设计）。
  小助手未运行时会退化成「在播放列表里筛选该文件夹」，不会按键无反应。
- 根目录需要**手填一次**绝对路径（浏览器不给），填错时配置面板会列出尝试过的路径帮你定位。
- 页面部署在 https 上时，访问本机服务要过 Private Network Access 预检；极少数情况下会被拦，
  此时改用 `pnpm dev` / `pnpm preview` 从本地地址打开页面即可。
